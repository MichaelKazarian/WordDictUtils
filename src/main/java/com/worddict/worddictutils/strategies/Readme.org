Пакет strategies був створений для розв'язання трьох фундаментальних проблем при збереженні слів у файловій системі (ext4).
1. Проблема Bucketing-у (Кошиків)

    Проблема: Якщо зберігати всі слова (наприклад, 50,000 JSON-файлів) в одній папці, робота з ФС стає незручною (зависання ls, проблеми з масками *.json).

    Розв'язання: Стратегія розбиває файли по папках-кошиках (Buckets) на основі першої літери.

    Результат: Замість однієї папки з 50к файлів, ми маємо ~30 папок по 1.5к файлів, що значно полегшує навігацію та обслуговування.

2. Проблема умляутів та діакритики (Unicode)

    Проблема: У європейських мовах літери з діакритикою (ä, é, ñ, ї) технічно є різними символами. Без стратегії слово "Über" потрапило б у папку "Ü/", а слово "Uran" — у папку "U/". Це створює хаос у дереві каталогів (сотні папок для кожного символу Unicode).

    Розв'язання: Використання Unicode Normalization (NFD) у LatinStrategy. Ми «розкладаємо» символ Ü на U + umlaut і відкидаємо діакритику для визначення папки.

    Результат: Усі варіації літери (ü, û, ù) групуються в одну фізичну папку "U/", що робить структуру передбачуваною.

3. Проблема Регістру (Case Sensitivity) на ext4

    Проблема: На ext4 файли Test.json та test.json — це різні об'єкти.

        В англійській мові це зазвичай одне слово (нам потрібно їх злити в один файл test.json).

        В німецькій мові Test (іменник) та test (корінь дієслова) мають різне значення.

    Розв'язання: * LatinStrategy (для англійської) примусово робить toLowerCase() для імені файлу.

        CaseSensitiveLatinStrategy (для німецької) зберігає оригінальний регістр слова в назві файлу.

    Результат: Ми зберігаємо лінгвістичну точність мови, не порушуючи логіку роботи файлової системи.
